Como ler

  • audited_system é o centro: tudo pertence a um sistema auditado. Cada audit_run (execução) tem muitos finding (achados).
  • Só três relações têm chave estrangeira real: audit_run.system_id, finding.audit_run_id e finding_suppression.system_id. As demais (mcp_*, pending_action, review_suggestion, rule_proposal, system_engine_config, audit_progress) guardam o id, mas o banco não impede apagar o pai.
  • fingerprint é o que liga o mesmo achado entre execuções e as supressões: finding_suppression é única por (system_id, fingerprint).
  • Segredos nunca ficam em texto: tokens e segredos de webhook são cifrados (*_enc) e a chave do MCP guarda só o hash (key_hash).
  • Todas as datas são timestamptz (V5: as antigas foram lidas como UTC). audit_run.disabled_sides veio na V6.

Histórico das migrações

  • V1 baseline com as 12 tabelas, chaves, únicos e índices.
  • V2 remove checagens antigas de status e categoria em bancos legados.
  • V3 remove o índice redundante idx_suppression_system.
  • V4 completa bancos antigos (cria o que faltar, sem alterar o que existe).
  • V5 todas as datas passam para timestamptz.
  • V6 adiciona audit_run.disabled_sides.
